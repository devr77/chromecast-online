        How to test a stream on Chromecast

        1. Open in Chrome

          Open Cast Test Sender in Google Chrome or Microsoft Edge on a computer or Android phone connected to the same Wi-Fi network as your Chromecast or Google TV.

        2. Connect

          Press Connect or the Cast icon and pick your device. The Default Media Receiver launches on the TV, or your own receiver if you entered a custom app ID.

        3. Cast and control

          Pick a sample or paste your own MP4, HLS or DASH URL and press Cast now. Then play, pause, seek, change volume, toggle subtitles and watch every event in the log.

        Everything you need to debug Google Cast playback

        • Every major format

          Progressive MP4 and WebM, adaptive HLS, MPEG-DASH and Smooth Streaming, plus audio and images.

        • Custom receivers

          Test your own receiver application ID before you publish it, including styled and custom Web Receivers.

        • Subtitles and tracks

          Attach a WebVTT subtitle file and switch captions on or off from the sender.

        • Live and queues

          Load live streams, line up a queue of items, and skip forward or back between them.

        • Custom namespaces

          Send JSON messages on your own urn:x-cast: namespace and read the receiver's replies.

        • Shareable test links

          Copy a link that pre-fills the stream, so QA and teammates can reproduce an issue in one click.

        Frequently asked questions

        What is a Cast test sender?

        A Cast test sender is a web page that uses the Google Cast Web Sender SDK to connect to a Chromecast, Google TV or Cast-enabled speaker and load a media URL on it. Developers use it to check that streams, subtitles and custom receiver apps play correctly on real Cast hardware.

        Why doesn't the Cast button appear or find my Chromecast?

        Use Google Chrome or Microsoft Edge on desktop or Android, open the page over HTTPS, and make sure your computer and Cast device are on the same Wi-Fi network. Guest networks, VPNs and routers with client or AP isolation often block Cast discovery.

        Which formats does the Default Media Receiver support?

        The Default Media Receiver plays MP4 (H.264/AAC), WebM (VP8/VP9), HLS, MPEG-DASH and Smooth Streaming video, MP3, AAC, FLAC, Opus and WAV audio, and JPEG, PNG, GIF, BMP and WebP images. HEVC, 4K and HDR support depends on the specific Cast device.

        Why does my HLS or DASH stream fail with LOAD_FAILED?

        Adaptive streams are fetched by the receiver with JavaScript, so the manifest and every segment must be served over HTTPS with an Access-Control-Allow-Origin header. For HLS streams that use fragmented MP4 segments, set the HLS segment format options to FMP4.

        How do I test my own custom Cast receiver?

        Enter your receiver application ID from the Google Cast SDK Developer Console in the Receiver app ID field and apply it. Unpublished receivers only run on devices whose serial number is registered in the console; after registering, restart the device and wait about 15 minutes.

        Can I cast a local file from my computer?

        The Cast device downloads media itself, so the file must be reachable at a URL on your network or the internet. Serve the folder with a local web server and use your computer's LAN IP address rather than localhost. Adaptive streams also need HTTPS and CORS headers.

        Is my data sent to a server?

        No. The tool runs entirely in your browser. Media URLs are sent directly to your Cast device, and your recent casts are saved only in your browser's local storage.

        Does it work on iPhone, Safari or Firefox?

        No. The Google Cast Web Sender SDK is only supported in Chrome and Chromium-based Edge on Windows, macOS, Linux, ChromeOS and Android. On iOS you need a native app that uses the Cast iOS SDK.
